A harness engineering glossary

Brendan Cody-Kenny, October 2026

Many ideas in harness engineering already have names in search-based software engineering (SBSE). Harness engineering is about two years old and its terms are still changing. Each row below gives one idea and its name in SBSE, in software engineering, in harness engineering and in agent factories, with a reference for each term.

The agent factory column uses the 2026 sense of the term, from Addy Osmani. "Software factory" also names Cusumano's Japanese factories and Greenfield and Short's model-driven factories (2004), and this table covers neither.

Strength says how closely the SBSE term matches the harness term. Equivalent means both name the same role and the words could be swapped. Analogy means the roles match and the mechanism differs. Weak means the terms do related but different jobs. No match means one field has no counterpart.

Two loops and an evaluator

A harness has two nested loops and an evaluator. The outer loop chooses a task, a model and a budget, and then retries, merges or sets the task aside. The inner loop is the agent inspecting, editing and testing. The test suite checks each candidate and returns the result. The inner loop is already a search, so the outer loop picks between searches. The closest SBSE work for the outer loop is algorithm selection and hyper-heuristics.

Cost

Genetic programming uses a cheap random mutation and runs thousands of evaluations. An agent writes a patch from the repository's code and tests, at far higher cost per candidate, and a harness can afford a handful of evaluations per task. With so few evaluations, the result depends on the agent and the tests.
